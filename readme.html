灰度路由全流程：打标 · 选址 · 透传

一条请求如何被判为灰度、如何落到试点实例、如何在服务间保持灰度——全流程三个环节分别由两个 Starter 承载：打标在网关（hint-tagging-spring-boot-starter），选址与透传在通用链路（hint-routing-spring-boot-starter），业务代码零侵入。

① 打标：谁走灰度

打标只发生在链路最前端。GrayHintFilter（GlobalFilter，order=10000，先于负载均衡选址 10150）解析登录柜员身份，命中灰度规则就写 X-SC-LB-Hint: trial，否则清除该 Header。判定依据是柜员号 / 角色，不是 URL 参数。

1.1 条件装配：只有网关、且显式开启才生效

hint-tagging-spring-boot-starter/src/main/java/demo/hint/tagging/TaggingHintAutoConfiguration.java

@AutoConfiguration
@ConditionalOnClass(name = "org.springframework.cloud.gateway.filter.GlobalFilter")
@ConditionalOnProperty(prefix = "gray.hint", name = "enabled", havingValue = "true")
@EnableConfigurationProperties(GrayHintProperties.class)
public class TaggingHintAutoConfiguration {
    @Bean
    @ConditionalOnMissingBean(GrayHintFilter.class)   // 业务可自定义 Bean 覆盖打标策略
    GrayHintFilter grayHintFilter(GrayHintProperties properties) {
        return new GrayHintFilter(properties);
    }
}

@ConditionalOnClass 保证非网关应用（service-a/b）即使误引依赖也不装配；gray.hint.enabled 不配则过滤器不加载。

1.2 核心过滤器：无条件覆盖，杜绝伪造

hint-tagging-spring-boot-starter/src/main/java/demo/hint/tagging/GrayHintFilter.java

@Override
public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
    TellerIdentity teller = resolve(exchange);                       // ① 解析柜员身份
    String hint = isGray(teller) ? properties.getLane() : null;      // ② 灰度判定
    var request = exchange.getRequest().mutate().headers(headers -> {
        headers.remove(HINT_HEADER);                                 // ③ 先无条件清除外部传入的 Hint
        if (hint != null) headers.set(HINT_HEADER, hint);            // ④ 命中灰度才写 trial
    }).build();
    return chain.filter(exchange.mutate().request(request).build());
}

private boolean isGray(TellerIdentity teller) {
    // 规则一：柜员号在灰度名单；规则二：柜员带有灰度角色。命中任一即灰度。
    return properties.getTellers().contains(teller.tellerNo())
            || teller.roles().stream().anyMatch(properties.getRoles()::contains);
}

1.3 身份从哪来：登录态优先，Header 仅演示兜底

private TellerIdentity resolve(ServerWebExchange exchange) {
    TellerIdentity fromToken = parseToken(
            exchange.getRequest().getHeaders().getFirst(HttpHeaders.AUTHORIZATION));
    if (fromToken != null) return fromToken;       // 优先：JWT 中的 tellerNo / roles
    // 演示兜底：X-Teller-No / X-Teller-Roles。生产上由鉴权过滤器验签 token 后写入。
    ...
}
生产要点：① 身份头必须由鉴权过滤器在验签 JWT 后写入，并先清除外部同名 Header，防止冒用柜员号进灰度；② 灰度名单放 Apollo 配置中心动态维护（见 1.4），扩量回滚不发版。

1.4 灰度名单配置：柜员号维护在 Apollo，不在配置文件

灰度名单（柜员号 / 角色）以 Apollo 配置中心为准（application 命名空间），扩量、回滚、调整试点柜员都只改配置不发版。配置内容以根目录 apollo-gray-hint.properties 为唯一来源，可直接粘贴到 Apollo Portal，或用脚本一键推送并发布：

# Apollo application 命名空间：apollo-gray-hint.properties
gray.hint.enabled=true        # 打开 GrayHintFilter
gray.hint.lane=trial          # 试点泳道标记值，与试点实例 metadata 的 hint 一致
gray.hint.roles=GRAY_TRIAL    # 灰度角色名单，多个用英文逗号分隔
gray.hint.tellers=8888        # 柜员号灰度名单，多个用英文逗号分隔
# 一键推送并发布（--prune 顺带清理命名空间里多余的键）
APOLLO_PORTAL=http://localhost:18070 APOLLO_APP_ID=gray-demo APOLLO_ENV=DEV \
APOLLO_ADMIN_USER=apollo APOLLO_ADMIN_PASSWORD=admin \
python3 scripts/apollo_push.py --prune

配置类 GrayHintProperties（前缀 gray.hint）绑定以上四个属性。柜员 8888 被配置了 GRAY_TRIAL 角色后，该柜员发起的所有操作都是灰度——无需每个接口再传参数。

1.5 改名单不重启：Apollo 动态刷新

gateway/src/main/java/demo/hint/gateway/ApolloGrayHintRefresher.java

@ApolloConfigChangeListener(interestedKeyPrefixes = "gray.hint.")
public void onChange(ConfigChangeEvent event) {
    GrayHintProperties target = properties.getIfAvailable();
    if (target == null) return; // gray.hint.enabled 未开启时没有该 Bean
    Binder.get(environment).bind("gray.hint", Bindable.ofInstance(target)); // 原地重绑定单例
}

在 Apollo 里修改名单并发布后，网关实时生效，无需重启。本地演示可以不开 Apollo（APOLLO_ENABLED 缺省 false），此时 application-gray.yml 中的 gray.hint.* 仅作缺省值 / 离线兜底；生产上名单只在 Apollo 维护，接入时置 APOLLO_ENABLED=true 并配置 APOLLO_APP_ID / APOLLO_META。

② 选址：灰度落到试点实例

打标之后是 Spring Cloud LoadBalancer 的标准选址流程。两个约定把 Hint 翻译成实例选择：服务侧在 Eureka 注册元数据，调用侧由 LaneSupplier 按 Hint 过滤候选实例。

2.3 LaneSupplier：带标匹配试点，普通绝不进试点

hint-routing-spring-boot-starter/src/main/java/demo/hint/starter/LaneSupplier.java

@Override
public Flux<List<ServiceInstance>> get(Request request) {
    if (request.getContext() instanceof RequestDataContext context
            && context.getClientRequest() != null
            && StringUtils.hasText(context.getClientRequest().getHeaders().getFirst("X-SC-LB-Hint"))) {
        // 带标请求：沿用 Spring 原生逻辑，优先匹配，匹配不到则回退全部实例。
        return super.get(request);
    }
    // 普通请求：只能选没有标签的实例。没有普通节点就返回空列表，不能转到试点。
    return discovery.get(request).map(this::ordinaryOnly);
}

private List<ServiceInstance> ordinaryOnly(List<ServiceInstance> instances) {
    return instances.stream().filter(instance ->
            !StringUtils.hasText(instance.getMetadata().get("hint"))).toList();
}

该 Supplier 通过 LoadBalancer 子容器装配，业务工程无需导入：

hint-routing-spring-boot-starter/src/main/java/demo/hint/starter/ServletHintConfiguration.java

@Bean
ServiceInstanceListSupplier hintSupplier(ConfigurableApplicationContext context,
                                        LoadBalancerClientFactory factory) {
    var discovery = ServiceInstanceListSupplier.builder().withBlockingDiscoveryClient().build(context);
    return new LaneSupplier(discovery, factory);
}
请求类型候选实例试点节点缺失时
带 Hint=trialhint=trial 的试点实例优先允许回退全部实例
无 Hint（普通）仅无标签实例返回空列表，请求失败，绝不转到试点

③ 透传：服务间保持同一泳道

A 调 B 用 Feign 发出的是全新的 HTTP 请求，不会自动继承 A 收到的 Header。透传通过一个全局 Feign 拦截器完成，业务接口不加任何 Header 参数。

3.1 ForwardHint：A 的所有 Feign 调用统一透传

hint-routing-spring-boot-starter/src/main/java/demo/hint/starter/ForwardHint.java

@Override
public void apply(RequestTemplate template) {
    // Feign 发出的是新 HTTP 请求，不会自动继承 A 收到的 Header。
    // 这一个拦截器对 A 的所有同步 Feign 调用生效，业务方法不用改。
    if (RequestContextHolder.getRequestAttributes() instanceof ServletRequestAttributes attrs) {
        String id = attrs.getRequest().getHeader("X-Request-Id");
        if (id != null) template.header("X-Request-Id", id);
        String hint = attrs.getRequest().getHeader("X-SC-LB-Hint");
        if (hint != null && !hint.isBlank()) {
            template.header("X-SC-LB-Hint", hint);
        }
    }
    // 没有 Header 就什么也不做，不补 main、不用 A 自己的身份替换请求标签。
}

3.2 自动装配：仅 Servlet + Feign 环境

hint-routing-spring-boot-starter/src/main/java/demo/hint/starter/FeignHintAutoConfiguration.java

@AutoConfiguration
@ConditionalOnWebApplication(type = ConditionalOnWebApplication.Type.SERVLET)
@ConditionalOnClass(name = {"feign.RequestInterceptor", "jakarta.servlet.http.HttpServletRequest"})
public class FeignHintAutoConfiguration {
    @Bean
    @ConditionalOnMissingBean(ForwardHint.class)
    ForwardHint forwardHint() { return new ForwardHint(); }
}
透传只搬两样东西：Hint（决定下游选址）和 请求编号（便于日志串联）。B 收到请求后不需要再判断柜员身份——整条链路的灰度属性在入口就已确定。

④ 全链路时序：一次灰度请求

步骤组件关键动作
①网关 GrayHintFilter + 日志过滤器解析柜员 8888 / GRAY_TRIAL → 命中灰度 → 写 X-SC-LB-Hint: trial
②LoadBalancer + LaneSupplier（网关 → A）读 Hint → 选中 hint=trial 的 A 实例
③service-a ForwardHintFeign 调用 hint-service-b，透传 Hint 与请求编号
④LoadBalancer + LaneSupplier（A → B）读 Hint → 选中 hint=trial 的 B 实例
⑤网关日志过滤器记录实际落点与状态码，请求结束
[abc12345] ① 网关收到 GET /api/demo，设置 Hint=trial，准备调用 A
[abc12345] ② A 收到请求，实际实例=a-trial:19093，GET /api/demo，Hint=trial
[abc12345] ③ A 发起 Feign 请求：GET /internal/demo，目标服务=hint-service-b，透传 Hint=trial
[abc12345] ④ B 收到请求，实际实例=b-trial:19094，GET /internal/demo，Hint=trial
[abc12345] ⑤ 网关结束，实际 A 地址=http://127.0.0.1:19093/api/demo，响应状态=200 OK

日志前缀的 [8 位请求编号] 在网关、A、B 三处相同，用 ⌘F 搜索即可串起同一次请求。普通柜员的请求全程 Hint 为空，落点必须是 a-main:19091 / b-main:19092。

⑤ 接入与配置

5.1 依赖：两个 Starter，各司其职

<dependency>
    <groupId>demo.hint</groupId>
    <artifactId>hint-routing-spring-boot-starter</artifactId>
    <version>1.0.0</version>
</dependency>

<!-- 仅网关：按柜员身份打标 -->

    <groupId>demo.hint</groupId>
    <artifactId>hint-tagging-spring-boot-starter</artifactId>

</dependency>

Starter 自动识别响应式网关与 Servlet 服务，业务代码不需要注解、不需要扫描配置、不改 Controller 和 Feign 接口。技术栈：Java 17、Spring Boot 3.5.0、Spring Cloud 2025.0.0、同步 Feign。

5.2 网关路由：只管转发，不再管打标

gateway/src/main/resources/application-gray.yml

spring:
  cloud:
    gateway:
      server:
        webflux:
          routes:
            # 打标不再看 URL 参数：所有请求走同一条路由，
            # 灰度 Hint 由 GrayHintFilter 按登录柜员身份（柜员号/角色）决定。
            - id: demo
              uri: lb://hint-service-a
              predicates:
                - Path=/api/demo
          globalcors:            # 放行 readme.html 按钮演示的跨域请求
            cors-configurations:
              "[/**]":
                allowed-origin-patterns: "*"
                allowed-headers: "*"
                allowed-methods: "*"
    loadbalancer:
      cache:
        enabled: false
      hint-header-name: X-SC-LB-Hint
为什么用 --spring.config.name=application-gray 而不是 --spring.profiles.active=gray：profile 方式会与原 application.yml 合并加载，路由列表按下标合并会导致新旧规则混杂；config.name 只加载新文件，行为确定。原 Query=flag 打标方式（application.yml）已移除，网关只保留柜员身份打标。
